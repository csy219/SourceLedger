## 一、三个核心概念：分层与关系

它们是从上到下的依赖关系：

```
业务代码 → Session（会话） → 会话工厂（session_factory）
                                  ↓
                            Engine（数据库引擎）
                                  ↓
                            连接池（Connection Pool）
                                  ↓
                            真实数据库（MySQL/PostgreSQL等）
```

### 1. 连接池（Connection Pool）

最底层的组件，**管理一堆已经建立好的数据库物理连接（TCP 连接）**。

- 类比：银行提前开好的营业窗口，每个窗口都是一条和总部的专线。
- 作用：避免每次操作数据库都重新建立连接（TCP 握手、认证、权限校验开销极大），用完归还、重复使用；同时控制最大连接数，保护数据库不被压垮。

### 2. 会话工厂（session_factory）

中间层，**一个 “生产 Session 的模具”**。

- 类比：银行叫号机，你取一次号，就给你分配一个窗口。
- 本质：通常由 SQLAlchemy 的 `sessionmaker()` 创建，提前绑定好数据库引擎和连接池配置，调用一次就产出一个新的 Session，不用每次重复写连接参数。

### 3. Session（会话）

上层，也就是你代码里 `with ... as session:` 里的 `session`，**是一次数据库交互的 “工作单元”**。

- 类比：你单次去银行办业务的全过程，从叫号到办完离开。
- 作用：负责增删改查、跟踪对象修改、管理事务；它底层会从连接池里 “借” 一条连接来用，用完再 “还” 回连接池。
